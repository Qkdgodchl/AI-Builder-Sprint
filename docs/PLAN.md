# 📜 픽셀 케어 (Pixel Care) 선행 약정 CLM 플랫폼 통합 기획서 (PLAN.md)

> **AI Builder Sprint 2026 최종 서비스 기획 명세서**  
> **한 줄 정의**: AI와 대화하며 기부·봉사 의사를 정리하고, 맞춤 선행을 추천받아 약정서 생성부터 전자서명·증빙·갱신까지 전 과정을 관리하는 **CLM(Contract Lifecycle Management) 기반 선행 플랫폼**

---

## 🎯 1. 해결하는 문제 & 최종 서비스 흐름

### 1.1 문제 정의 (Problem Definition)
- **실제 신청으로 이어지지 않는 문제**: 말로만 참여 의사를 표현하고 실제 약정 및 신청까지 연결되지 않음.
- **파편화된 양식 및 문서**: 단체마다 신청서와 동의서 양식이 다르고 이메일·종이·파일로 서명 문서가 분산됨.
- **사후 관리의 부재**: 정기후원 갱신, 봉사 이행, 서명 상태 및 증빙을 한곳에서 지속적으로 관리하기 어려움.

### 1.2 선행 약정 CLM 통합 프로세스 (End-to-End Flow)
```
[의향 발견] ──► [AI 상담 & 파싱] ──► [맞춤 활동 추천] ──► [신청 정보 수집]
     │
     ▼
[약정·동의서 자동 생성] ──► [검토 및 수정] ──► [모두싸인 전자서명 요청]
     │
     ▼
[전자서명 완료 & PDF 증빙 보관] ──► [활동·후원 이행 관리] ──► [갱신 및 다음 선행 추천]
```

## 📱 2. 전체 화면 구성 (하단 4대 탭 & 단체 대시보드)

### 2.1 사용자 앱 화면 구성
1. **🏠 홈 (Home - AI 상담 진입점)**
   - 상단 핵심 영역: *"어떤 선행을 하고 싶으신가요?"* `[AI와 대화 시작하기]`
   - 주요 요소: 관심 분야 기반 추천 활동, 최근 약정 상태, 서명 대기 알림, 정기후원 갱신 알림
   - 빠른 메뉴: 🤝 봉사 찾기 | ❤️ 기부하기 | 🏛️ 부산 고향사랑기부 | 🏺 유산기부·문화유산 후원
2. **🎁 선행하기 (Action Catalog)**
   - 카테고리: 전체 | 봉사 | 일반 기부 | 부산 고향사랑기부 | 문화유산 후원 | 유산기부
   - 검색, 지역 필터, 일시/정기 필터, 모집 상태 및 활동 카드 렌더링
3. **💬 커뮤니티 (Community & Verification)**
   - CLM 연동: 약정/봉사 완료된 활동과 연결된 "인증된 선행" 배지 게시글 작성
   - 선행 후기, 봉사 인증 사진 등록, 기부·후원 인증
4. **❤️ 내 기록 (My CLM Records)**
   - 내 활동: 신청한 봉사, 참여 예정, 완료 봉사, 일반기부, 정기후원, 고향사랑기부, 문화유산 후원, 유산기부 의향
   - 내 약정서: 서명 완료 PDF, 감사추적인증서, 약정서 상세, 갱신/변경/해지 요청

### 2.2 🏢 단체·기부처 대시보드 (Organization Admin Dashboard)
- **대시보드 메인**: 전체 약정 수, 신규 약정, 서명 대기, 서명 완료, 이행 중, 갱신 예정
- **약정 & 봉사 관리**: 신청자 승인/거절, 약정서 템플릿 등록, 문서 검토, 서명 재요청, 완료 문서 다운로드

## 🤖 4. Upstage AI 파이프라인 & 에이전트 설계

### 4.1 Upstage API 3대 역할 분담
1. **Solar LLM (대화 & 구조화)**:
   - 사용자 선행 의도 파악, 누락 항목 질문, 사용자 의향 요약(JSON), 계약 문구 초안 생성 및 검토
2. **Information Extract (항목 추출 및 검증)**:
   - 단체가 등록한 약정서에서 필드 추출, 서명 완료 문서 핵심 정보 추출, 필수 입력값 구조화 검증
3. **Document Parse (템플릿 분석)**:
   - 단체 PDF/이미지 템플릿 업로드 분석, 기존 종이 약정서 디지털화 및 표/문단 구조 추출

### 4.2 선행 계약 에이전트 Tool 구성
- `search_opportunities`: 조건(봉사/기부, 지역, 가능날짜)에 맞는 선행 활동 검색
- `extract_commitment_intent`: 대화 내용에서 약정 정보 JSON 구조화
- `validate_commitment`: 필수 항목 및 비즈니스 규칙 검증 (금액, 주기, 날짜, 동의 누락 여부)
- `generate_contract`: 유형별 약정서 및 동의서 문서 생성
- `request_signature`: 모두싸인 전자서명 요청 API 호출
- `get_signature_status`: 전자서명 진행 상태 및 완료 콜백 동기화

## 🔄 5. 모두싸인 연동 & CLM 계약 상태 머신 (11 States)

### 5.1 계약 생애주기 상태 (Contract States)
```
[DRAFT 작성중] ──► [IN_REVIEW 검토중] ──► [APPROVED 승인완료]
                       │
                       ▼
[SIGN_REQUESTED 서명요청] ──► [SIGNING 서명진행중] ──► [SIGNED 서명완료]
                                                          │
                                                          ▼
[COMPLETED 이행완료] ◄── [RENEWAL_DUE 갱신예정] ◄── [ACTIVE 약정이행중]
```
- **예외 상태**: `REVISION_REQUESTED` (수정 요청), `CANCELLED` (취소), `EXPIRED` (만료)

### 5.2 모두싸인 연동 필수 저장 데이터
- 내부 약정 ID, 모두싸인 문서 ID (`modusignDocumentId`), 서명 요청 ID, 서명자 ID, 현재 서명 상태, 서명 완료 PDF URL, 감사추적인증서 URL

## 🎯 6. 개발 우선순위 (Roadmap)

1. **1단계: 특별상 핵심 MVP (최우선 구현)**
   - 사용자/단체 역할 로그인, 5대 선행 유형, Solar LLM 의향 상담 및 JSON 구조화, 약정/동의서 생성, 모두싸인 전자서명 연동, 내 기록 PDF 관리, 단체 대시보드
2. **2단계: CLM 완성도 강화**
   - 약정 수정 요청, 계약 버전 관리, 정기후원 갱신 알림, Webhook 예외 처리, Information Extract 검증
3. **3단계: 본상 경쟁력 강화**
   - 선행 인증 커뮤니티, AI 후기 초안 생성, 선행 뱃지 및 활동 리포트
